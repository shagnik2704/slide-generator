## Code Formatting Standards

### 1. Import Organization

```python
# Standard library imports (alphabetically sorted)
import json
import os
import time
from pathlib import Path
from typing import Optional, List

# Third-party imports (alphabetically sorted)
from fastapi import APIRouter, HTTPException, Depends
from pydantic import BaseModel

# Local application imports (grouped by type)
from src.api.auth import get_current_user, TokenData
from src.api.common.constants import ALLOWED_EXTENSIONS

from src.api.exceptions import ValidationError
```

### 5. Error Handling Pattern

```python
try:
    # Operation
    result = process_data(data)
    return APIResponse.success_response(result)
except ValueError as e:
    raise ValidationError(str(e))
except FileNotFoundError:
    raise NotFoundError("Resource")
except Exception as e:
    logger.error(f"Unexpected error: {e}", exc_info=True)
    raise InternalServerError("Operation failed")
```

## Naming Conventions

- **Files**: `snake_case.py`
- **Classes**: `PascalCase`
- **Functions/Variables**: `snake_case`
- **Constants**: `UPPER_SNAKE_CASE`
- **Private**: `_leading_underscore`

## Best Practices

1. **Separation of Concerns**: Routes should be thin, delegate to services
2. **Dependency Injection**: Use FastAPI's Depends for dependencies
3. **Type Hints**: Always use type hints for function parameters and returns
4. **Error Handling**: Use custom exceptions, not generic Exception
5. **Logging**: Use structured logging with appropriate levels
6. **Validation**: Validate at the API boundary (Pydantic models)
7. **Constants**: Extract magic numbers and strings to constants
8. **DRY**: Don't repeat yourself - extract common code to helpers
